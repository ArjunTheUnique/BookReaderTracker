## 4. Root-Cause & Boundary Diagnosis

Two independent root causes, both environmental, neither a logic defect:

1. **Manifest gap — no lockfile in the builder sandbox.** `pubspec.lock` is generated by `flutter pub get`, which needs the Flutter SDK. With no SDK, the builder could not resolve or honestly invent versions for the three transitive/utility packages, and correctly chose to say so rather than guess. The pins were therefore left as placeholders. The work order allowed those rows to be "recorded from pubspec.lock" — so the fix is simply to produce that lockfile.
2. **Receipt gap — no Dart toolchain.** The work order's Return Package requires the execution output of `tests/test_m1_library_store.dart`. Without Dart/Flutter, the builder substituted a Python harness that mirrors the *rules*. That is useful corroboration — my own independent re-derivation of the same rules also passes (28/28) — but it is not the Dart code running, and it cannot catch a compile error, a drift API mismatch, or the `part 'm1_library_store.g.dart'` generation step.

Secondary hardening finding (not a gate blocker, fix while you are here): the `IdempotencyLedger` table's primary key is `idempotencyKey` alone. Because the key is not namespaced by `op`, a caller that reuses one key string across two different operations (e.g. an `add_book` then an `update_progress`) would be mis-read as a replay. The replay guard branches on the *current* op while the stored row records the *original* op, so the returned shape can be wrong. Low real-world risk (callers generate unique keys), but it should be tightened.

**Fix C (hardening) — namespace the idempotency key by operation.** Change the `IdempotencyLedger` primary key from `{idempotencyKey}` to the composite `{op, idempotencyKey}`, and update `_replayIfSeen` / `_rememberKey` to match. This makes the replay guard correct even if a key is reused across ops. This is a small change contained entirely within M1 (its socket shape does not change), so it does not require a Registry version bump — but bump the Module Passport to v1.0.1.

**Unchanged and confirmed correct — do not alter:** the IN/OUT contract field names and types; the error codes E1–E9; the "repeated key on `update_progress` returns `saved:false`" rule; the 6-category / 6-book caps; `schema_version = 1`.
