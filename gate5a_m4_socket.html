Gate 5A · Module Work Order — M4 Daily Engine

M4 Daily Engine — the day's picture, composed

M4 turns raw progress into one clean day view: total pages today and a per-book percentage, ready for the widget (M5) and the grid (M7). M1 already stores the per-day rows; M4 owns the timezone-aware "today" and the anomaly guard, and it never pushes to the widget itself.

Caller & injected port
M5 / M7
"give me today's picture"
Clock (port)
timezone-aware now — fakeable in tests
M4Daily Engine
IN{ as_of_date: "YYYY-MM-DD", timezone_offset_min: int }
OUT — success{ ok: true, data: { date, total_pages_today: int, per_book: [ { book_id, pages_today: int, pct_today: float 0–100 } ] }, schema_version: 1 }
failure: { ok:false, error:{ code, message, field? } }
Declared error shapes:E1E2E4
Forbidden: no widget push (M5 owns it) and no file reads. M4 reads via M1 read_daily and composes; it never writes.
Downstream & what comes back
← M1 read_daily
raw per-day rows for the date
anomaly guard
clock jump → clamp negatives to 0 (S5)
→ M5 / M7
the composed day view
Mandatory 5-Part Verification Suite — definition of done
TEST 1
Happy-Path Acceptance
Progress logged for a date → correct total_pages_today and per-book pct_today.
TEST 2
Boundary & Idempotency
Empty day → zeros, not an error; clock jump → negatives clamped to 0.
TEST 3
Error-Shape Coverage
One case each for E1, E2, E4 — exact error.code asserted.
TEST 4
Registry Seam Check
OUT keys exactly {date, total_pages_today, per_book}; per_book keys exact; schema_version == 1.
TEST 5
Smoke & Health Probe
Boots against fresh M1; M4→M1 seam works end to end.
